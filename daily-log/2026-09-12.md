---

## The problem I ran into & how I solved it
* **What I was trying to do:** Running kubectl after restarting Docker
* **The error:** ``The connection to the server 127.0.0.1:6443 was refused`.`
* **What actually caused it:** Docker had stopped, so the Kind containerized control plane node was offline.
* **How I fixed it:** Started Docker and ran `docker start k8s-lab-control-plane`.
* **Takeaway / lesson learned:** kubectl communicates exclusively with `kube-apiserver` over HTTPS; all state is stored in `etcd`.

---

## Key takeaways from today
- `etcd` is the single source of truth for the entire cluster; backing it up is critical in production.
- Use `kubectl explain <resource>.<field>` to inspect API specs right in the terminal without opening documentation.
