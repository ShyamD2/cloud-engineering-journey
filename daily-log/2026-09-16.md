## The problem I ran into & how I solved it
* **What I was trying to do:** Launching the background FastAPI core daemon from the floating launcher without getting terminated on exit.
* **The error:** `[WinError 10061] No connection could be made because the target machine actively refused it` when parent process completed.
* **What actually caused it:** Standard `subprocess.Popen` on Windows tied the child daemon process to the calling process group, terminating it when the launcher script exited.
* **How I fixed it:** Added `0x00000008 | 0x00000200` (`DETACHED_PROCESS` and `CREATE_NEW_PROCESS_GROUP`) flags to `Popen`, and implemented dual redundancy: direct in-process Python bridging via `FloatingAgentAPI.execute_command` with automatic fallback to `/api/device/execute`.
* **Takeaway / lesson learned:** For desktop assistants, in-process native bridging provides faster response times and zero network overhead compared to pure HTTP loops.
