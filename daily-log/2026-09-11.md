# 2026-09-11 — Day 42: Passwordless AWS Deployments with OIDC

Configured OpenID Connect (OIDC) between GitHub Actions and AWS IAM today. Storing static `AWS_ACCESS_KEY_ID` in repository secrets always felt sketchy. OIDC is so much cleaner.

---

## What I worked on today
- Created an IAM OIDC Identity Provider for GitHub Actions.
- Created an IAM Role with an OIDC trust policy restricting access strictly to repository `ShyamD2/cloud-engineering-journey`.
- Ran `aws sts get-caller-identity` inside GitHub Actions using temporary STS tokens.

---

## Commands I ran
```bash
aws iam create-open-id-connect-provider --url https://token.actions.githubusercontent.com --client-id-list sts.amazonaws.com --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1
aws iam create-role --role-name GitHubActionsDeploymentRole --assume-role-policy-document file://oidc-trust-policy.json
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Authenticating from GitHub Actions
* **The error:** ``Error: Not authorized to perform sts:AssumeRoleWithWebIdentity`.`
* **What actually caused it:** I had a typo in the repository name in the IAM Trust Policy's `sub` claim condition.
* **How I fixed it:** Fixed the claim to `repo:ShyamD2/cloud-engineering-journey:*` in the Trust Policy.
* **Takeaway / lesson learned:** OIDC eliminates credential leakage risks: GitHub receives temporary credentials valid for 1 hour that auto-expire.

---

## Key takeaways from today
- OIDC federation is the security industry standard for CI/CD cloud authentication.
- Zero static AWS access keys stored in GitHub Secrets.
