## The problem I ran into & how I solved it
* **Mobile Touch Trackpad Permission Denial (Error 5)**:
  * **What happened**: When moving the cursor on the mobile web trackpad, the cursor did not move.
  * **Root cause**: Background threads (like the Uvicorn worker thread) are not attached to the interactive Windows input desktop (`default`). Win32 calls `GetCursorPos`, `SetCursorPos`, and `mouse_event` returned `ERROR_ACCESS_DENIED` (Error 5). Additionally, rapid touchmove events fired unthrottled HTTP requests, causing connection queue saturation.
  * **Fix**:
    1. Implemented `_ensure_desktop()` via `OpenInputDesktop` and `SetThreadDesktop` in `mouse_agent.py` and `keyboard_agent.py`, granting full input injection rights.
    2. Re-engineered the mobile trackpad with sub-millisecond full-duplex WebSockets (`/ws/trackpad`) and client-side `requestAnimationFrame` touch batching.
    3. Converted desktop streaming into non-blocking async executor tasks and defaulted the video stream to on-demand toggle to ensure zero input lag.
