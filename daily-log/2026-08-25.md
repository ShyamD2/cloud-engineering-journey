# 2026-08-25 — Day 25: AWS CloudWatch Metrics, Log Filters & Alarms

Observability day! Installed the Unified CloudWatch Agent on EC2 to collect memory utilization and created log metric filters to notify me whenever 500 errors spike.

---

## What I worked on today
- Installed `amazon-cloudwatch-agent` on Linux instances to stream RAM and disk utilization (which AWS hypervisor doesn't see by default).
- Created CloudWatch Log Group `/aws/ec2/nginx-access`.
- Built a Metric Filter counting HTTP 5xx errors and linked it to a CloudWatch Alarm with SNS notifications.

---

## Commands I ran
```bash
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a fetch-config -m ec2 -s -c file:/opt/aws/amazon-cloudwatch-agent/bin/config.json
aws logs put-metric-filter --log-group-name /aws/ec2/nginx-access --filter-name HTTP500Errors --filter-pattern '[..., status = 5*, ...]' --metric-transformations metricName=500Count,metricNamespace=NginxMetrics,metricValue=1
aws cloudwatch put-metric-alarm --alarm-name High500ErrorRate --metric-name 500Count --namespace NginxMetrics --statistic Sum --period 60 --threshold 10 --comparison-operator GreaterThanThreshold --evaluation-periods 1 --alarm-actions arn:aws:sns:ap-south-1:...:DevOpsAlerts
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Testing the alarm by generating fake 500 errors
* **The error:** `Alarm stayed in `INSUFFICIENT_DATA` even after several errors were logged.`
* **What actually caused it:** The metric filter had no default value configured for quiet periods when no logs matched.
* **How I fixed it:** Updated the metric transformation setting `defaultValue: 0` so data points emit continuously.
* **Takeaway / lesson learned:** Always set `defaultValue: 0` on metric filters so CloudWatch alarms don't get stuck in `INSUFFICIENT_DATA`.

---

## Key takeaways from today
- Standard EC2 metrics only measure CPU and hypervisor network/disk I/O; memory and disk space require the CloudWatch Agent.
- SNS topics can forward alerts to Slack, Discord, or automated Lambda remediations.
