# 2026-08-13 — Day 13: Internet Gateway & Public Route Tables

Today I connected my custom VPC to the internet using an Internet Gateway (IGW) and configured route tables for my public subnets.

---

## What I worked on today
- Created and attached `igw-prod` to my custom VPC.
- Created a custom Public Route Table and added the default route: `0.0.0.0/0 -> igw-prod`.
- Associated my public subnets with this route table and verified external reachability.

---

## Commands I ran
```bash
aws ec2 create-internet-gateway --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=prod-igw}]'
aws ec2 attach-internet-gateway --internet-gateway-id igw-01234567 --vpc-id vpc-01234567
aws ec2 create-route --route-table-id rtb-01234567 --destination-cidr-block 0.0.0.0/0 --gateway-id igw-01234567
aws ec2 associate-route-table --subnet-id subnet-01234567 --route-table-id rtb-01234567
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Connecting via SSH to a test EC2 instance in the public subnet
* **The error:** `Connection timed out on port 22 even though the instance had a public IPv4 address assigned.`
* **What actually caused it:** The subnet was still associated with the VPC's Main Route Table, which didn't have a route to the Internet Gateway.
* **How I fixed it:** Explicitly associated the subnet with my custom Public Route Table containing `0.0.0.0/0 -> igw-xxxx`.
* **Takeaway / lesson learned:** A public IP on an EC2 instance is completely useless unless the subnet's route table has an active path to an attached Internet Gateway.

---

## Key takeaways from today
- Only one Internet Gateway can be attached per VPC.
- An Internet Gateway is highly available and managed by AWS; it doesn't bottleneck bandwidth like a single VM would.
