## The problem I ran into & how I solved it
* **What I was trying to do:** Ensure seamless interoperability between relative path references when scripts are invoked from root vs from their respective subdirectories.
* **The error:** Running `python day-02-log-errors/log_error_finder.py` from root failed to locate `server.log` when relying on default relative path.
* **What actually caused it:** `os.path.exists("server.log")` resolves against current working directory (`CWD`), which differs when run from root vs module directory.
* **How I fixed it:** Used `os.path.dirname(os.path.abspath(__file__))` as an automatic fallback when target files are not found in the current CWD.
* **Takeaway / lesson learned:** Production CLI utilities must resolve relative paths using script-relative anchors or explicit arguments to ensure portability across different execution environments and CI runners.
