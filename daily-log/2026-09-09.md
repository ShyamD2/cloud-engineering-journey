# 2026-09-09 — Day 40: Container Security Hardening & Trivy Scanning

Container security day! Running containers as root is super risky. Today I hardened my Docker images and set up automated vulnerability scanning with Trivy.

---

## What I worked on today
- Added non-root user creation (`USER appuser`) to production Dockerfiles.
- Scanned images with Trivy (`trivy image --severity HIGH,CRITICAL`).
- Tested running containers with read-only root filesystems (`--read-only`).

---

## Commands I ran
```bash
trivy image python:3.11
trivy image api-service:hardened
docker run --rm --read-only --tmpfs /tmp:rw,noexec api-service:hardened
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Running container with `--read-only` flag
* **The error:** ``PermissionError: [Errno 30] Read-only file system: '/tmp/cache.tmp'`.`
* **What actually caused it:** The app tried writing temporary cache files to `/tmp`, which was read-only.
* **How I fixed it:** Mounted an in-memory tmpfs volume at `/tmp` (`--tmpfs /tmp:rw,noexec,nosuid,size=64m`).
* **Takeaway / lesson learned:** Read-only containers block attackers from modifying code or dropping binaries, while tmpfs gives apps safe temporary scratch space.

---

## Key takeaways from today
- Never run container processes as root (UID 0).
- Dropping Linux capabilities (`--cap-drop=ALL`) dramatically reduces what an attacker can do if they exploit a vulnerability.
