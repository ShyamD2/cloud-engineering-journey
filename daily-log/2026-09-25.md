## The problem I ran into & how I solved it
* **What I was trying to do:** Run automated CI test suites in headless GitHub Actions runners without physical audio hardware or cloud AWS credentials.
* **The error:** CI failed on PyAudio initialization (`PaErrorCode -9996: Invalid device`) and Boto3 credential lookup timeouts.
* **What actually caused it:** GitHub Actions virtual machines have no physical audio devices and no default AWS IAM credentials configured.
* **How I fixed it:**
  1. Guarded audio engine initialization with safe mock fallbacks when `pygame.mixer` or PyAudio cannot bind hardware.
  2. Mocked AWS STS and Boto3 calls during CI test runs using environment variable `CI=true` checks.
* **Takeaway / lesson learned:** Cloud CI/CD environments are stateless and headless. Any code depending on physical hardware, sound cards, or live cloud endpoints must provide reliable mock fallbacks during automated testing.
