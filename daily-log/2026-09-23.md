## The problem I ran into & how I solved it
* **What I was trying to do:** Stream and filter a multi-megabyte log file safely without failing on invalid characters.
* **The error:** `UnicodeDecodeError: 'utf-8' codec can't decode byte 0x80 in position 1024: invalid start byte`.
* **What actually caused it:** Log files occasionally contain binary traces, non-UTF-8 characters, or truncated byte sequences.
* **How I fixed it:** Specified `errors="replace"` in `open(log_path, mode="r", encoding="utf-8", errors="replace")`. This safely substitutes corrupted bytes with replacement markers rather than crashing the parsing pipeline.
* **Takeaway / lesson learned:** Production I/O scripts must always specify character error replacement strategies to maintain fault tolerance against real-world dirty log data.
