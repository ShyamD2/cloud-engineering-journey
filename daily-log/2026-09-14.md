# 2026-09-14 — Day 45: Kubernetes Services & Ingress Controller Routing

Covered Kubernetes networking and Ingress routing today. Pods are ephemeral and their IPs change constantly, so Services and Ingress are how you keep traffic flowing properly.

---

## What I worked on today
- Created a `ClusterIP` service to give application pods a stable internal IP.
- Installed the NGINX Ingress Controller using Helm.
- Configured an Ingress resource to route HTTP traffic based on host and path.

---

## Commands I ran
```bash
kubectl expose deployment web-deployment --port=80 --target-port=8080 --name=web-service
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm install ingress-nginx ingress-nginx/ingress-nginx
kubectl get svc ingress-nginx-controller
curl -H 'Host: app.local' http://localhost/api
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Routing traffic through Ingress to backend service
* **The error:** `Ingress returned `HTTP 503 Service Temporarily Unavailable`.`
* **What actually caused it:** The Service selector `app: web-app` didn't match the pod label `app: web`.
* **How I fixed it:** Fixed the selector in `service.yaml` to match the pod labels exactly.
* **Takeaway / lesson learned:** Kubernetes Services route traffic to Pods dynamically using Endpoints matched via label selectors.

---

## Key takeaways from today
- ClusterIP is for internal traffic; NodePort opens a static port on nodes; Ingress provides Layer 7 HTTP routing.
- Ingress saves money by routing multiple domain names and paths through a single cloud load balancer.
