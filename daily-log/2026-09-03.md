# 2026-09-03 — Day 34: Terraform Variables, Locals & Sensitive Values

Cleaned up hardcoded values in my Terraform code today using variables, locals, and output blocks. Also learned how to keep sensitive secrets from leaking into terminal outputs.

---

## What I worked on today
- Moved hardcoded IDs and CIDRs into typed variables in `variables.tf`.
- Used `locals` to construct standardized resource tags across all resources.
- Marked database passwords with `sensitive = true`.

---

## Commands I ran
```bash
terraform plan -var='environment=staging'
terraform output -json
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Running terraform plan with database credentials
* **The error:** `The plaintext database password was printed directly to stdout in the plan preview.`
* **What actually caused it:** The input variable wasn't marked as sensitive.
* **How I fixed it:** Added `sensitive = true` to the variable definition in `variables.tf`.
* **Takeaway / lesson learned:** `sensitive = true` hides values from `plan` and `apply` output, but remember that the secret is still stored inside the state file—secure that S3 bucket!

---

## Key takeaways from today
- Use `locals` for computed internal values and `variables` for configurable module inputs.
- Variable precedence: CLI `-var` > `terraform.tfvars` > Environment variables > Defaults.
