# 2026-08-17 — Day 17: VPC Endpoints: S3 Gateway Endpoints vs PrivateLink

Learned how to save money on AWS data transfer today. Routing S3 traffic through a NAT Gateway is a great way to waste cloud budget. Gateway Endpoints solve this for free.

---

## What I worked on today
- Created an S3 Gateway Endpoint and attached it to private route tables.
- Provisioned Interface Endpoints (PrivateLink) for Systems Manager (SSM).
- Uploaded large test files to S3 from a private instance with the NAT Gateway route disabled.

---

## Commands I ran
```bash
aws ec2 create-vpc-endpoint --vpc-id vpc-01234567 --service-name com.amazonaws.ap-south-1.s3 --route-table-ids rtb-private-1a
aws s3 cp large-test-file.bin s3://my-private-backup-bucket/
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Testing S3 upload from private instance
* **The error:** ``Could not connect to the endpoint URL: https://s3.ap-south-1.amazonaws.com`.`
* **What actually caused it:** The instance's security group had an outbound rule that blocked port 443 HTTPS.
* **How I fixed it:** Allowed outbound HTTPS (port 443) on the instance Security Group.
* **Takeaway / lesson learned:** Gateway Endpoints update route tables with AWS prefix lists, but instances still need outbound port 443 open in their security groups.

---

## Key takeaways from today
- S3 and DynamoDB Gateway Endpoints are 100% free and have no throughput bottlenecks.
- Interface Endpoints create an ENI in your subnet and charge an hourly fee plus per-GB data processing.
