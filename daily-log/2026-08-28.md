# 2026-08-28 — Day 28: Amazon API Gateway: HTTP APIs & CORS Configuration

Connected my Lambda function to Amazon API Gateway today using an HTTP API (v2). It's much simpler and cheaper than legacy REST APIs.

---

## What I worked on today
- Created an HTTP API with Lambda proxy integration.
- Configured routes: `POST /shorten` and `GET /{short_code}`.
- Configured CORS settings to allow requests from web browsers.

---

## Commands I ran
```bash
aws apigatewayv2 create-api --name UrlShortenerApi --protocol-type HTTP --target arn:aws:lambda:ap-south-1:...:function:url-shortener
aws lambda add-permission --function-name url-shortener --statement-id apigateway-access --action lambda:InvokeFunction --principal apigateway.amazonaws.com
curl -X POST https://api-id.execute-api.ap-south-1.amazonaws.com/shorten -H 'Content-Type: application/json' -d '{"url":"https://aws.amazon.com"}'
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Testing the API from a browser frontend
* **The error:** ``Access to fetch at ... has been blocked by CORS policy: Response to preflight request doesn't pass access control check`.`
* **What actually caused it:** The browser sent an `OPTIONS` preflight request before the `POST`, and API Gateway wasn't handling it.
* **How I fixed it:** Enabled CORS in API Gateway settings with `AllowOrigins=['*']`, `AllowMethods=['GET', 'POST', 'OPTIONS']`, and `AllowHeaders=['Content-Type']`.
* **Takeaway / lesson learned:** Browsers always send an HTTP OPTIONS preflight request before cross-origin POST requests with JSON headers; API Gateway must respond to it.

## Key takeaways from today
