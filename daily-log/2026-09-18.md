  - Implemented dynamic DPI scaling in `_draw_cursor_on_image`:
    `scale_x = phys_w / sys_w`, `scale_y = phys_h / sys_h`
    `cx = int(raw_cx * scale_x)`, `cy = int(raw_cy * scale_y)`

  - Registered `/cyberlock` with Telegram's native command list via `setMyCommands` and added full help documentation.
  - Zero-blackout physical screen lock barrier allows locking room displays while retaining 100% active live video stream and control from the phone.
- **Floating HUD: Hardware Voice Hearing & Sub-Second Latency (<405ms)**:
  - Fixed microphone hearing issue on Intel Smart Sound Technology Digital Microphones: Implemented active RMS chunk probing to detect live hardware inputs and clamped ambient room noise calibration between 180 and 400 (preventing room noise spikes from calibrating up to 3190+ and deafening the recognizer).

## The problem I ran into & how I solved it
* **What I was trying to do:** Ensuring the mouse pointer on the live video stream accurately reflects the user's real cursor location.
* **The error:** The drawn cursor was rendering ~93 pixels above the real mouse location on screen.
* **What actually caused it:** On Windows, display scaling was set to 125%. Windows API `GetCursorInfo` returned logical coordinates (`1536×864`), but `ImageGrab.grab()` captured the physical display resolution (`1920×1080`). Drawing unscaled logical coordinates on a 1080p frame caused a vertical and horizontal offset.
* **How I fixed it:** Dynamically queried `GetSystemMetrics` for logical bounds, compared them against `img.size` to calculate the scale factors (`1.25x`), and mapped coordinates accurately before rendering the high-contrast pointer.
* **Takeaway / lesson learned:** Never assume 1:1 pixel mapping on modern high-DPI displays. Always scale OS logical coordinates to framebuffer physical dimensions.
