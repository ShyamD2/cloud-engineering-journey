# 2026-08-26 — Day 26: AWS Systems Manager: Eliminating SSH Port 22

One of my favorite security wins: completely closing inbound port 22 across my EC2 fleet and using AWS Systems Manager (SSM) Session Manager instead.

---

## What I worked on today
- Attached the AWS managed policy `AmazonSSMManagedInstanceCore` to the EC2 instance role.
- Removed all inbound port 22 rules from instance Security Groups.
- Verified CLI shell access using `aws ssm start-session`.
- Configured session logging to an encrypted S3 bucket for compliance.

---

## Commands I ran
```bash
aws ec2 revoke-security-group-ingress --group-id sg-web --protocol tcp --port 22 --cidr 0.0.0.0/0
aws ssm start-session --target i-0123456789abcdef0
aws ssm describe-instance-information --output table
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Starting SSM session to a private instance
* **The error:** ``TargetNotConnected: i-0123456789abcdef0 is not connected.``
* **What actually caused it:** The private instance didn't have outbound access to reach the public SSM API endpoints.
* **How I fixed it:** Created VPC Interface Endpoints for `ssm`, `ssmmessages`, and `ec2messages` in the private subnet.
* **Takeaway / lesson learned:** SSM requires HTTPS outbound connectivity to AWS endpoints; Interface Endpoints let private instances connect without needing a NAT Gateway.

---

## Key takeaways from today
- Session Manager logs every command and keystroke to CloudWatch or S3.
- No more managing SSH private keys or dealing with leaked key files.
