```bash
kubectl rollout history deployment/web-deployment
kubectl rollout undo deployment/web-deployment
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Deploying updated container
* **The error:** `Pods entered `CrashLoopBackOff` with `OOMKilled (Exit Code 137)`.`
* **What actually caused it:** I set the memory limit to `64Mi`, but the application needed `96Mi` during startup.
* **How I fixed it:** Increased memory limit to `256Mi` with request at `128Mi` in `deployment.yaml`.
* **Takeaway / lesson learned:** Exit code 137 in Kubernetes means Out Of Memory (OOMKilled) by the Linux kernel.

---

## Key takeaways from today
- Readiness probes prevent Kubernetes from sending user traffic to a Pod before it's ready.
- Rolling updates ensure old pods are only terminated after new pods pass their readiness checks.
