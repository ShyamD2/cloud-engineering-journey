## The problem I ran into & how I solved it
* **What I was trying to do:** View a file whose filename is simply a dash (`-`) in the terminal.
* **The error:** Running `cat -` causes the command to hang, waiting for standard input (stdin).
* **What actually caused it:** Most POSIX utilities interpret a standalone `-` as standard input (stdin) or the beginning of a command-line flag.
* **How I fixed it:** Used the explicit relative path syntax `cat ./-` (or input redirection `cat < -`), which clearly designates the dash as a filesystem filename rather than a stream operator.
* **Takeaway / lesson learned:** In automated bash and DevOps deployment scripts, always prefix relative arguments with `./` to prevent user-supplied filenames from masquerading as command flags.

---

## Key takeaways from today
- **Virtual Pseudo-Filesystem**: `/proc` files take zero space on disk because they exist strictly in memory. They provide an instantaneous window into Linux kernel runtime telemetry.
- **True Available RAM**: Linux uses free memory for disk caching; evaluating system RAM by `MemFree` is inaccurate. `MemAvailable` is the true indicator of capacity before swapping occurs.
