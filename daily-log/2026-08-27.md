# 2026-08-27 — Day 27: AWS Lambda: Execution Lifecycle & Cold Starts

Diving into serverless computing today with AWS Lambda. Understanding the execution environment lifecycle is key to writing performant Lambda functions in Python.

---

## What I worked on today
- Wrote a Python 3.11 Lambda function with structured JSON logging.
- Moved heavy SDK client initializations and database connections outside the handler function to reuse warm execution contexts.
- Tested invocation latencies across different memory sizes (128MB, 512MB, 1024MB).

---

## Commands I ran
```bash
zip function.zip lambda_function.py
aws lambda create-function --function-name api-handler --runtime python3.11 --role arn:aws:iam::197550036081:role/LambdaBasicRole --handler lambda_function.handler --zip-file fileb://function.zip --memory-size 256 --timeout 10
aws lambda invoke --function-name api-handler --payload '{"key":"value"}' response.json
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Invoking the Lambda function with test payload
* **The error:** `Function terminated with `Task timed out after 3.00 seconds`.`
* **What actually caused it:** The default Lambda timeout is only 3 seconds, which wasn't enough time to establish external connections on a cold start.
* **How I fixed it:** Increased timeout to 15 seconds and bumped memory to 512MB (which gives it more CPU power too).
* **Takeaway / lesson learned:** In AWS Lambda, increasing memory also scales CPU power and network bandwidth proportionally.

---

## Key takeaways from today
- Code outside `def handler(event, context):` runs only once per cold start and stays warm across subsequent calls.
- Cold starts happen when AWS spins up a new microVM for your function.
