## The problem I ran into & how I solved it
* **What I was trying to do:** Ensure that calling `interrupt_service.interrupt()` during live audio playback stopped `pygame.mixer` immediately and unlocked the audio file so temporary MP3 files could be unlinked cleanly.
* **The error:** Windows threw `PermissionError: [WinError 32] The process cannot access the file because it is being used by another process` when trying to clean up temporary audio files after an interruption.
* **What actually caused it:** `pygame.mixer.music.stop()` halts playback asynchronously, but the underlying SDL audio driver retains an open file handle on the active `.mp3` file for a few milliseconds until `pygame.mixer.music.unload()` is called.
* **How I fixed it:** Added `pygame.mixer.music.unload()` immediately after `pygame.mixer.music.stop()` inside `interrupt_service.py`, wrapped file cleanup in a retry loop with a 50ms backoff, and ensured temporary files are generated with unique UUIDs.
* **Takeaway / lesson learned:** On Windows systems, file locking during media playback requires explicit driver unloading before attempting filesystem mutations or unlinks.

## Key takeaways from today
- **Sub-10ms Voice Interruption**: Seamless conversational UX requires immediate acoustic barge-in. Giving the user multiple modalities to stop output (voice keywords, keyboard hotkeys, and REST endpoints) creates a responsive and trustworthy companion.
