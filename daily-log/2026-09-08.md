## The problem I ran into & how I solved it
* **What I was trying to do:** Connecting web app container to PostgreSQL container
* **The error:** ``ConnectionRefusedError: could not connect to server at 127.0.0.1:5432`.`
* **What actually caused it:** Inside a container, `localhost` refers to that specific container, not the other containers in the network.
* **How I fixed it:** Updated database host string to use the Docker Compose service name `db` (`postgres://user:pass@db:5432/app`).
* **Takeaway / lesson learned:** Docker's embedded DNS automatically resolves Compose service names to their container IP addresses inside user-defined networks.

---

## Key takeaways from today
- User-defined bridge networks provide internal DNS resolution; the default bridge network does not.
- Named volumes survive `docker compose down` and keep your database data safe.
