# 2026-08-22 — Day 22: Amazon S3 Security & Pre-Signed URLs

Explored S3 security features today. Made sure I understand Block Public Access, bucket policies, and how to grant secure temporary access to files using pre-signed URLs.

---

## What I worked on today
- Enabled all 4 S3 Block Public Access settings on a new bucket.
- Enforced SSE-KMS customer-managed key encryption by default.
- Generated a temporary pre-signed URL valid for 15 minutes to test time-limited file downloads.

---

## Commands I ran
```bash
aws s3api create-bucket --bucket secure-data-vault-2026 --region ap-south-1 --create-bucket-configuration LocationConstraint=ap-south-1
aws s3api put-public-access-block --bucket secure-data-vault-2026 --public-access-block-configuration 'BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true'
aws s3 presign s3://secure-data-vault-2026/report.pdf --expires-in 900
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Downloading the file using the pre-signed URL
* **The error:** `Got `HTTP 403 Forbidden` with `AccessDenied` in the browser.`
* **What actually caused it:** The file was encrypted with a custom KMS key, but the IAM role that generated the pre-signed URL lacked `kms:Decrypt` in the KMS Key Policy.
* **How I fixed it:** Updated the KMS Key Policy to allow the IAM role to perform `kms:Decrypt`.
* **Takeaway / lesson learned:** When S3 objects use KMS encryption, access checks require permissions on BOTH the S3 bucket policy and the KMS key policy.

---

## Key takeaways from today
- Pre-signed URLs are great for allowing client uploads/downloads directly to S3 without routing traffic through your web servers.
- Account-level Block Public Access is the ultimate safety net against accidental public buckets.
