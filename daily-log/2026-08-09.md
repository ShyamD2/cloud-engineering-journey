# 2026-08-09 — Day 9: AWS CLI Configuration & Profile Management

Week 2 starts! Moving into AWS today. I set up the AWS CLI properly on my machine and configured named profiles instead of dumping static credentials into default environment variables.

---

## What I worked on today
- Verified AWS CLI v2 installation.
- Configured `~/.aws/credentials` and `~/.aws/config` with dedicated IAM user `dev-cli-user`.
- Set default region to `ap-south-1` (Mumbai) and output format to `json`.
- Tested identity resolution using AWS STS.

---

## Commands I ran
```bash
aws --version
aws configure --profile dev-cli-user
aws sts get-caller-identity --profile dev-cli-user
export AWS_PROFILE=dev-cli-user
```

---

## The problem I ran into & how I solved it
* **What I was trying to do:** Checking caller identity with default profile
* **The error:** ``InvalidClientTokenId: The security token included in the request is invalid.``
* **What actually caused it:** I had old `AWS_ACCESS_KEY_ID` environment variables set in my shell from an old project that were conflicting with my newly configured profile.
* **How I fixed it:** Unset those environment variables (`unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY`) and let the CLI read cleanly from my configured profile.
* **Takeaway / lesson learned:** Environment variables always take precedence over `~/.aws/credentials` in the AWS CLI credential resolution chain.

---

## Key takeaways from today
- Never use the AWS root account for CLI or everyday work.
- `aws sts get-caller-identity` is the first command you should run in any script to verify who you're authenticating as.
